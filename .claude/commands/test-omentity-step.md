# Step-by-Step OMEntity Testing

Протестируй один DAG файл из `Dags samples/` с детальным анализом расхождений.

## Задача

1. Получи список файлов для тестирования:
   ```bash
   "c:\DevWB\AF Dags Helper\venv\Scripts\python.exe" "c:\DevWB\AF Dags Helper\test_step_by_step.py"
   ```

2. Протестируй файл (начни с #0 или укажи номер):
   ```bash
   "c:\DevWB\AF Dags Helper\venv\Scripts\python.exe" "c:\DevWB\AF Dags Helper\test_step_by_step.py" <номер>
   ```

3. При обнаружении расхождения:
   - Внимательно изучи код из отчёта
   - Определи точную причину расхождения
   - Классифицируй проблему

4. Типы расхождений и действия:

   **API не детектирован:**
   - Причина: API connection передаётся через параметр функции или op_kwargs
   - Решение: Описать какую логику резолвинга нужно добавить в утилиту

   **Таблица не найдена:**
   - Причина: SQL формируется динамически или таблица в bulk_dump
   - Решение: Проверить паттерны в коде функции

   **Несовпадение сервера:**
   - Причина: connection_id не имеет маппинга
   - Решение: Предложить добавить в `config/server_mapping.yaml`

   **Лишняя entity:**
   - Причина: Ложное срабатывание или неполный эталон
   - Решение: Проанализировать SQL и определить правильность

5. Сформулируй:
   - Конкретную причину каждого расхождения
   - Рекомендацию (маппинг / улучшение утилиты / ожидаемое ограничение)

6. Спроси пользователя: перейти к следующему файлу?

## Ожидаемый результат

- Детальный анализ каждого расхождения с объяснением причины
- Конкретные рекомендации по исправлению
- Понимание каких паттернов утилита пока не поддерживает
