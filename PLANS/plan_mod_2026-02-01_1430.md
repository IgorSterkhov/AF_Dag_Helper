# План: Игнорирование суффикса _d при тестировании

**Дата:** 2026-02-01 14:30

## Проблема

При тестировании возникают ложные расхождения из-за суффикса `_d`:
- Существующий в DAG: `do-ch6.buffer.na_boxes_shk_d`
- Сгенерированный: `do-ch6.buffer.na_boxes_shk`

Эти FQN должны считаться эквивалентными.

## Решение

Нормализовать FQN перед сравнением — удалять суффикс `_d` из имени таблицы.

## Изменения

### Файл: `test_against_samples.py`

**1. Добавить функцию нормализации FQN (после импортов, ~строка 32):**

```python
def normalize_fqn(fqn: str) -> str:
    """
    Нормализует FQN для сравнения.
    Удаляет суффикс _d из имени таблицы.

    Пример: do-ch6.buffer.na_boxes_shk_d -> do-ch6.buffer.na_boxes_shk
    """
    parts = fqn.rsplit('.', 1)  # Разделяем на prefix и table
    if len(parts) == 2:
        prefix, table = parts
        if table.endswith('_d'):
            table = table[:-2]
        return f"{prefix}.{table}"
    return fqn
```

**2. Обновить класс OMEntityInfo — нормализовать в `__eq__` и `__hash__`:**

```python
@dataclass
class OMEntityInfo:
    """Информация об одном OMEntity."""
    entity_type: str  # TABLE, API
    fqn: str

    def __hash__(self):
        return hash((self.entity_type, normalize_fqn(self.fqn)))

    def __eq__(self, other):
        if not isinstance(other, OMEntityInfo):
            return False
        return (self.entity_type == other.entity_type and
                normalize_fqn(self.fqn) == normalize_fqn(other.fqn))
```
